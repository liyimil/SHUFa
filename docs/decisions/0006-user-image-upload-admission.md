# ADR-0006：用户图片在入队前执行服务端安全准入

日期：2026-07-18  
状态：已接受

## 背景

移动端通过短时效签名 URL 把作品直接上传到私有对象存储。客户端声明的 MIME、字节数和宽高只能用于预约资源，不能证明对象确实是安全图片；对象存储的 `Content-Type` 同样由上传请求提供。只校验这些元数据会让格式伪装、像素炸弹和截断图片进入分析队列。

## 决策

- 创建上传会话时只允许 JPEG、PNG、WebP，限制 10 MB、单边 256～12000 像素及总计 4000 万像素。
- 完成上传时先核对私有对象的长度和类型，再通过有上限的 Range 读取对象；即使校验期间对象变化，也最多读取预约长度加一个字节。
- API 使用 Sharp 从文件内容识别真实格式，按 EXIF 方向核对真实宽高，仅接受单帧位图，并强制完成一次解码；元数据读取成功不能代替完整解码。
- 文件头、长度、尺寸、帧数、像素预算或解码不符合要求时，API 使用现有条件状态变更抢占该待上传记录，删除私有对象并返回固定错误码，不创建分析任务。
- Worker 后的 Python 图像质量服务仍保留 4000 万像素限制和完整解码，作为异步处理边界的纵深校验，不能因为 API 已校验而移除。

## 结果

用户上传只有在服务端实际解析通过后才进入分析队列，客户端声明和对象元数据不再作为可信图片证据。生产对象存储仍需保持私有桶、短签名时效、请求大小限制和生命周期清理；真实 S3 兼容实现的 Range、删除及并发覆盖行为必须在 Staging 冒烟中复核。
