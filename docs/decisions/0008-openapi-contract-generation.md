# ADR-0008：从运行时路由生成可校验的 OpenAPI 契约

日期：2026-07-18  
状态：已接受

## 背景

NestJS 已能展示 Swagger 页面，但此前生成文档只有路由和操作标识，没有可供客户端使用的请求、响应 Schema。移动端和 Web 端各自维护接口类型，服务端字段或状态码变化时只能在运行期发现偏差。

## 决策

- Nest 路由扫描结果继续作为路径、HTTP 方法和 `operationId` 的唯一来源，不另写一份平行路由清单。
- 使用显式增强层为已纳入契约的操作补充请求体、响应体、路径参数、鉴权与组件 Schema；运行时 Swagger 和静态生成脚本调用同一个文档构造函数。
- 提交稳定排序的 `packages/api-contract/openapi.json`，再由 `openapi-typescript` 生成只读 TypeScript 类型。生成文件不再由 Prettier 二次改写。
- CI 同时重新生成 OpenAPI 和 TypeScript 类型并执行漂移检查；任何未提交的契约变化都使检查失败。
- Mobile、Web 和 Admin 直接消费共享契约包中的操作类型。80 个公开操作全部具有具体请求/响应、参数和鉴权契约；契约测试同时校验操作总数、手机号与 Web Cookie 会话、练习内切换范字、后台鉴权边界、变更请求体、UUID 参数和 CSV 响应。
- 不把“路由已被扫描”误报为“Schema 已完整覆盖”。新增路由只有同时加入显式增强层、生成类型和契约测试后，才能计入完整覆盖。

## 结果

运行时文档、静态契约和客户端类型不再由三套手工定义驱动，状态码与字段变化可以在 CI 中提前暴露。代价是新增或修改接口时必须同步增强层和契约测试，不能依赖空响应定义生成弱类型客户端。
